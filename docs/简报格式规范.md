# 简报格式规范（brief.md / Web 看板统一）

> 用户反馈：**"内容质量看着还可以，但是格式风格不满意，且看着乱，需要优化和美化，并且尽量每日统一。"**
> 本规范是 M6a 的第一部分（**先修格式，再做增强**）。

---

## 一、逐条回应反馈

| 反馈 | 规范 |
|---|---|
| 头条应附来源链接/标题 | ✅ 头条下方固定一行：`来源：<平台> · <标题> · [原文](url)` |
| 总览挤在一起 | ✅ 改为**分条列点**，每条一个主题，不再是一整段 |
| 主编点评没用足 md 格式 | ✅ 拆成带图标的小节（见下） |
| 加图形图标丰富内容 | ✅ 全篇统一图标体系 |
| 条目详略不一、排版混乱 | ✅ **所有条目统一结构**，不再"有的详细有的没有" |
| 详细解析不够一目了然 | ✅ 改为**表格 + 短标签**或折叠区块 |
| 每日统一 | ✅ 模板固化 + 空字段用占位符，不省略 |

## 四、实现要求

1. **模板固化**：`render/markdown.py` 用统一模板，**不允许条目有/无字段导致结构漂移**
2. **空值占位**：未生成的字段显示 `—` 或"（未生成）"，保持表格列数一致
3. **头条必带来源**：`来源 / 标题 / 链接 / 平台标签 / 热度` 五行信息固定
4. **总览分条**：LLM 输出结构化为 `overview_bullets[]`，每条带一个主题图标 + 一个小标题
5. **主编点评分节**：prompt 要求输出四个字段（core / cross_signal / counterintuitive / risk），
   渲染成四个带图标的小节
6. **Web 看板同步**：同样的结构与图标（Jinja2 模板复用一套样式定义）
7. **单测**：渲染结果断言——表格列数一致、头条必含链接、四个点评小节必存在

---

## 五、为什么先做格式

用户明确说"内容质量看着还可以，但格式不满意"。
**内容增强（为什么重要）是加分项，格式是及格线** —— 先让它每天读起来舒服且稳定，
再往里加东西，否则加得越多越乱。

而且格式规范化**几乎不需要额外 LLM 调用**（改渲染层 + prompt 输出结构），成本极低。
