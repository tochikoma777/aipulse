- 仓库公开准备：README（WIP + Roadmap）、MIT LICENSE、`.gitignore`、`.gitattributes`、`.github/workflows/ci.yml`。

### 踩的坑
1. **本机网络被"半个墙"挡着**：`huggingface.co`、`www.reddit.com`、`importai.substack.com` 在本环境被 DNS 污染（解析到 Facebook/Teredo 地址）后连接超时；而 `github.com`、`export.arxiv.org`、`hn.algolia.com` 可用但**极不稳定**（同一 URL 连续 3 次里 1 次成功）。
   - 应对：探测脚本默认 4 次重试 + 10s 连接超时，并为 `hf_papers` 配置了备用端点（`hf-mirror.com`，schema 与官方一致）。
2. httpx 0.28 的 `Response` 没有 `.ext`（只有 `.extensions`），缓存命中标记改用 `extensions` 字典。
3. `httpx.Timeout(connect=..., read=...)` 必须显式给 `default`，否则抛 ValueError。
4. GitHub Trending 偶发返回损坏的 gzip（`DecodingError`）→ 已加入可重试异常，并对该源请求 `Accept-Encoding: identity`。
5. SQLModel 表字段名为 `date` 时会与 `datetime.date` 类型注解冲突（pydantic 报 unevaluable-type-annotation）→ `from datetime import date as date_type`。
6. alembic autogenerate 生成的迁移引用 `sqlmodel.sql.sqltypes.AutoString` 但没 import → 在 `script.py.mako` 里补 `import sqlmodel`；mypy 对 migrations 目录整体排除。

### 关键决策
- **数据源结论一律以实测为准**，未通过探测的 URL 不留在生产配置里（详见 `docs/数据源手册.md`）。
- 中文 RSS 只剩"量子位"可用（仅摘要无正文），机器之心已下线 → **新闻板块依赖英文主干**，中文源全部标 `optional`。
- Reddit 在本环境完全不可达，`reddit_top.json` 快照缺失，已在手册中记录原因与后续补测方式。

### 实测结果（本地）
`aipulse collect --since 24h`：GitHub Trending 9 + arXiv 60 + HN 7 + RSS 32 = **108 条**，
5 个源成功、2 个源按设计跳过（hf_papers/reddit 标 `actions_only`）、**0 个失败、退出码 0**；写入 16 条 signals。

### 踩的坑与解决
1. **arXiv 严格按 24h 过滤会永远采空**：其 Atom `published` 是提交日，索引实际滞后 3-4 天（实测最新为 10-09，当天为 10-13）。
   → 新增 `lookback_days: 7` 配置并在放宽时打 warning。**这是真实数据才暴露的问题，不是文档能预见的。**
2. **单 feed / 单 subreddit / 单关键词失败会拖垮整个源**：RSS 第一次实现里 `respX` 未 mock 的异常把整源打成失败。
   → 三层都改成内部隔离（逐 feed / 逐 subreddit / 逐关键词），全部失败才算源级失败。
3. **HN 全部关键词失败时静默返回空** → 会伪装成"今天没热点"。改为显式抛 `CollectorError`（区分"真的空"与"全都挂了"）。
4. **本地库缺 `skip_cluster` 列**导致首次 collect 崩：迁移已生成但没执行 → 在 pipeline 入口加 `ensure_schema()`，
   库/表缺失时自动 upgrade 到 head。
5. **HF 备用端点语义**：用户填 `https://hf-mirror.com`（基址）即可，API 路径由代码拼接，避免让用户记忆 `/api/daily_papers`。
6. **测试时间漂移**：fixture 是冻结快照，用 `--since 24h` 写断言会随时间失效 → 测试统一用 30 天窗口。

### 关键决策
- `Item.id` 与 `content_hash` **源无关**（用 `arxiv:{id}` / `repo:{owner/name}` / 规范 URL 派生），
  这是"arXiv 与 HF 同一篇论文合并成一条"在存储层的落地方式；跨源合并后 `seen_in` 累加。
- `title_only` 标记保守合并：只要有任一源有正文，合并结果就不算仅标题。
- 不引入 `beautifulsoup4`：Trending 解析只用标准库正则 + 稳定结构（`h2>a[href]`、`itemprop`、`stars today` 文本）。

## M2 · 分析层 + LLM 抽象 + 每日简报（2026-10-14）

### 做了什么
- **前置**：RSS 内部改为每 feed 一个 asyncio 任务并发拉取（内部 semaphore 用 `http.max_concurrency`，仍受全局并发 6 限制）；确认 arXiv `lookback_days: 7` 已生效。
- `utils/text.py`：token 粗估（中文 1 字 1 token / 英文 3.5 字符）+ 摘要截断 ≤300 字。
- `schema/brief.py`：`DailyBrief` / `Section` / `ItemComment` / `ItemComments`（LLM 结构化输出契约）。
- `analysis/`：`signals.py`（增速 Δ/Δt）、`score.py`（热度公式，权重从 scoring.yaml 读，源内分位归一化，冷启动 velocity 取中性值）、`cluster.py`（jieba + TF-IDF + 余弦 0.35 + 连通分量，排除 skip_cluster）、`entities.py`（词典 + 正则，entities.yaml 外置）。
- `llm/`：`base.py`（LLMClient Protocol + NullLLM + FakeLLM + build_client）、`prompt.py`（Jinja2 + front-matter + prompt_version=sha256 前 8 位）、`openai_compat.py`（官方 openai SDK，fast/strong 双模型，json_schema/json_object 双通道）、`structured.py`（校验 + 一次修复重试 + 降级跳过）、`cache.py`（llm_cache 表）、`budget.py`（每日预算 + 降级）。
- `reasoning/brief.py` + `prompts/brief/{daily_brief,item_comment}.j2`；off 档数据版简报。
- `render/{markdown,json_out}.py` + `pipeline/daily.py` + CLI `analyze`/`brief`/`daily`。
- 新增依赖 `openai`（SSOT §8.2 明确要求官方 SDK）。

### 踩的坑
1. **`expire_on_commit` 是 Session 参数不是 engine 参数**：pipeline 在 session 关闭后渲染 items 触发 `DetachedInstanceError`。`create_engine(expire_on_commit=...)` 直接报错，正解是 `Session(engine, expire_on_commit=False)`。
2. **实体匹配器全局缓存被 `AIPULSE_ROOT` 污染**：测试里 monkeypatch root 后，缓存的正则用的是空 entities.yaml → 后续测试抽不到实体。改为以 `project_root()` 为键缓存，root 变化即重建。
3. **SQLModel `date` 字段名与 `datetime.date` 类型冲突**（沿用坑 30）：`schema/brief.py` 用 `from datetime import date as date_type`。
4. **`zip` 循环变量复用导致 mypy 类型冲突**：同一作用域两个 `for v in ...` 不同元素类型 → 改名。
5. openai 3.x 自带 `httpx2` 传输，`respx`（拦 httpx 1.x）无法 mock 它 → 结构化输出链路用桩客户端测，off 档用 `NullLLM`（零网络）测。

### 关键决策
- 热度公式的 `cross_bonus` 作为 0-1 加权和内的加成项（`0.05*(len(seen_in)-1)`），乘 100 后即"每个额外源 +5 分"。
- 全零 engagement 的源（rss/inbox）不做分位归一化（直接归 0），避免无信号维度被中性值抬高热度。
- `title_only`（skip_cluster）条目热度权重用 scoring.yaml 的 `title_only_weight: 0.35`。
- 聚类单点簇（成员 < min_cluster_size）不落库，避免"1 条即 1 主题"噪音。
- DeepSeek `json_schema` 实测结论归档见 `docs/数据源手册.md` §11（本机无 key，已内置双通道，待真实 key 验证）。

### 实测
- pytest 180 passed（M1 时 142）；ruff / mypy 全绿；coverage：analysis 91-97%、reasoning/brief 66%、collectors ≥80%、TOTAL 85%。
- `aipulse daily --skip-llm` 端到端产出 brief.md / daily.json / meta.json（off 档零 API 花费）。

## M3a · 预言系统（生成 + 手写 + 不可证伪拦截）（2026-10-14）

### 做了什么
- **开工第一件事（v1.7）**：`uv remove openai`，`openai` 与随它进来的 `httpx2/httpcore2/jiter/sniffio/truststore` 一并从 `uv.lock` 移除。
- **重写 `llm/openai_compat.py` 为 httpx 直连**：`POST {base_url}/chat/completions`，**仍走 `HttpClient`**（复用限速/重试/缓存/代理/UA，LLM 层关闭 HTTP 缓存）。错误分类：401/403 → `ConfigError` 不重试；429/5xx/超时 → HttpClient 的 tenacity 退避重试；其余 4xx → 记录并抛 `LLMError` 降级。
- **json_schema 运行时自动降级（§8.3）**：`llm.json_schema: auto|true|false`（默认 `auto`，兼容旧布尔写法）。auto 下首次带 `json_schema`，收到 400 且错误体含 `json_schema/response_format/unsupported` 关键词 → 自动改 `json_object` + prompt 内嵌 schema 重试，并进程内记住"该模型不支持"（模块级 `_JSON_SCHEMA_SUPPORT`），成功后也记住"支持"。降级原因写入 `llm_usage.error`（新增列 + 迁移 `a3c1d9f2e07b`）。
- **`schema/prediction.py`**：`Prediction`（含 v1.3 `origin`/`criteria*`）+ `PredictionBatch` + `Verdict`；confidence 步长 0.05 / horizon ∈{7,30,90,180} / category 枚举校验；`find_vague_phrases` 模糊措辞黑名单（"可能"用负向断言排除"不可能"）；`validate_prediction` 硬校验红线。
- **`prompts/predict/generate.j2`**（front-matter `model_tier: strong`）+ **`configs/criteria.yaml`** 判据模板库（github_new_repo / github_stars_reach / hn_story_points / entity_mentions / arxiv_paper_count / custom）。
- **`reasoning/predictor.py`**：上下文组装（Top N + 主题 + 实体频次）→ 结构化生成 → 硬校验 → 一次语义重写 → 仍不合法丢弃并记录。缺 `falsifiable_criteria` / 模糊措辞 / 证据 <2 一律拦截。
- **`store/repo_predictions.py`**：稳定 id（同天+同 statement+同 origin 幂等）；insert / list。
- **`cli/commands/predict.py`**：`predict`（自动生成，off 档空转）、`predict add`（**参数 + 缺参降级交互式向导**，判据模板用 `rich.prompt.Prompt.ask` 序号选择，末尾预览卡片 + 二次确认，`--yes` 跳过）、`predict list`；`verify`/`review` 留 M3b 占位。

### 踩的坑与解决
1. **Typer `invoke_without_command=True` 回调 + 子命令路由冲突**：回调在带子命令时也会被触发（实测 `predict list` 会先跑自动生成）。正解：回调首参加 `ctx: typer.Context`，`ctx.invoked_subcommand is not None` 时直接 return——这是"默认动作 + 子命令"的标准写法。
2. **`session.add` 后 `expire_on_commit` 默认过期**：`insert_predictions` commit 后 session 关闭，再读 `row.id/due_date` 报 `DetachedInstanceError`。沿用 M2 结论：`Session(engine, expire_on_commit=False)`。
3. **B008 误报**：`param: list[str] = typer.Option(None, ...)` 被 ruff B008 拦截（list 类型默认值），加 `# noqa: B008`（Typer 可重复选项标准写法）。
4. **缓存键未区分 json_schema/json_object**：两种 response_format 的响应若共用缓存键会互相污染 → 缓存键的 `response_model_name` 追加 `:js`/`:jo` 后缀区分。

### 关键决策
- **手写预言的红线落地**：`falsifiable_criteria` 是必填（红线），量化判据（`criteria`/`criteria_params`）是可选增强。选了判据模板 → `falsifiable_criteria` 自动渲染（如 `github_stars_reach(repo='...', threshold=90000)`）；选"不设定" → 向导追问一句话判据。证据 ≥2 仅约束 LLM 生成（手写不强求，§11.4）。
- **openai_compat 的 HttpClient 关闭 HTTP 层缓存**：LLM 响应走 `llm_cache` 表，不落 `http_cache`（POST 响应缓存语义不对）。
- 预算护栏在 `build_client` 里真正接上（M2 时 `budget` 参数默认 None 未生效），预言生成也受每日预算约束。

### 实测
- pytest **229 passed**（M2 时 180）；ruff / ruff format / mypy strict 全绿。
- 覆盖率：`openai_compat` **94%**（v1.7 目标 ≥80%）、`schema/prediction` 100%、`reasoning/predictor` 88%、`reasoning/criteria` 91%、`store/repo_predictions` 90%、**TOTAL 88%**。
- 非交互 `predict add`（--yes）、判据模板 `--criteria github_stars_reach --param ...`、`predict list --json`、`predict --skip-llm` 全链路实测通过；模糊措辞（"可能"）被拦截且退出码 1。

## M3b · 到期验证与统计（2026-10-14）

### 做了什么
- **`reasoning/verifier.py`**（★ 闭环）：双路径验证。`judge_criteria()` 量化判据查表**零 LLM**（6 模板：`github_new_repo` / `github_stars_reach` / `hn_story_points` / `entity_mentions` / `arxiv_paper_count` / `custom`）；语义路径 `retrieve_evidence()`（TF-IDF 余弦，窗口 `[生成日, due_date+3]`，Top 20）+ 充分度门槛（`≥3` 条过阈值或单条 `≥0.30`）→ 达标才调 `prompts/predict/verify.j2`。`verify_due_predictions()` 编排并写回 `status/verdict*`。
- **`prompts/predict/verify.j2`**：`model_tier: strong` / `temperature: 0.2`，只输出 `hit/partial/miss` 三值。
- **`store/repo_items.py`** 新增 `signals_max_value` / `signal_first_seen_map` / `count_entities_in_range` / `items_by_source`；**`store/repo_predictions.py`** 新增 `list_pending_due` / `save_verdict`。
- **`analysis/stats.py`** + **`render/scoreboard.py`**：命中率 / 加权分 / Brier / 校准分桶（含 `[0.05,0.5)`）/ 分组统计；记分板 Markdown 可贴 README，0 样本优雅空态。
- **CLI**：`predict verify`（`--due-date`/`--skip-llm`/`--json`/`--limit`）、`predict review <id> --verdict --note`（`verified_by=human`）、`stats --predictions`（`--json`/`--markdown`/`--out`）。
- **`pipeline/daily.py`** 接入 `auto_verify`：brief 后按 `pipeline.auto_verify` 调 `_auto_verify()`，异常只写 meta 不拖垮日报。
- **`configs/default.yaml`** 新增 `verify` 段 + `core/config.py::VerifySettings`。

### 踩的坑与解决
1. **mypy strict 拒绝 `dict[str, Any]` 存处理器**：`_CRITERIA_HANDLERS` 返回值被推断为 `Any` → 用 `Callable[...]` 类型别名精确标注。
2. **`float(dict.get(...))` 触发 `Any | None` 报错**：先取原始值列表再 `[float(v) for v in raw if v is not None]`。
3. **handler 的 `# type: ignore[return-value]` 不匹配**：实际错误码是 `no-any-return`，改用 `cast(Verdict, parsed)` 更干净。

### 关键决策
- **`unverifiable` 归 `status` 不归 `verdict`，且只由系统证据门槛产生**（v1.9）：LLM 一旦能输出就会变成逃避 miss 的软出口，命中率与 Brier 会被系统性美化。`Verdict` 契约保持 3 值不变。
- **证据不足不调 LLM**：既省成本，也避免模型在空白证据上"编造判定"；off 档语义预言直接走 grace/unverifiable。
- **窗口左界取生成日**（v1.9）：只覆盖 `due_date` 附近会把"生成后很早就兑现"的 hit 误判成 miss，系统性压低命中率。
- **`custom` 用受限 AST 白名单求值**（不用 `eval`）：支持 `new_repo/stars/points/mentions/papers` 五原语 + `and/or/not` 组合，非法表达式降级为"覆盖不足"而非报错。
- **miss 的前提是"覆盖已充分"**：某模板数据源在窗口内完全无观测（如无任何 HN 条目）→ `undetermined`，走 grace，不判 miss。

### 实测
- pytest **272 passed**（M3a 时 229，+43：criteria 22 / verifier 6 / stats 6 / CLI 8 / daily 1）；ruff / ruff format / mypy strict 全绿。
- 覆盖率：`analysis/stats` **100%**、`store/repo_predictions` 95%、`reasoning/verifier` 86%、`reasoning/criteria` 91%、`render/scoreboard` 82%、**TOTAL 88%**。
- **off 档完整闭环实测**（零 API，`llm_usage` 行数 = 0）：`predict add --criteria github_new_repo` → 写入 signal → `predict verify --skip-llm` 判 `hit`（`llm_calls=0`）→ `stats --predictions` 出命中率 100% / Brier 0.125 / 校准表。
- `predict review --verdict hit --note ...` 人工闭环生效（`verified_by=human`，计入统计）。
