# 模型使用策略（保守版）

> 目标：在**模型积分有限**的前提下，保证质量、且关键节点不掉链子。
> 适用于 M3a 及之后的所有阶段。

---

## 一、核心认知：省钱的主杠杆是「减少轮次」，不是「降低档位」

这是最容易搞反的一点。

**算一笔账**（以列表中的积分标价为参考）：

| 方案 | 成本 | 结果 |
|---|---|---|
| 弱模型磨 5 轮 | 0.11 × 5 = **0.55** | 可能还没解决，你还要反复看回复 |
| 强模型 1 轮解决 | 0.51 × 1 = **0.51** | 一次到位 |

**两者成本几乎相同，但强模型质量更高、你的等待与审阅时间大幅缩短。**

结论：
- ❌ 不要为了省钱在**复杂任务**上用弱模型反复磨 —— 这是假节省
- ✅ 要在**简单任务**（写测试、改格式、修 lint、机械批量）上坚持用便宜模型 —— 这是真节省

**所以保守策略的本质是：把钱精确地花在刀刃上，其余一律最便宜。**

## 二、分档使用表（保守版）

| 用途 | 推荐模型 | 单次 | 何时用 |
|---|---|---|---|
| **日常主力** | `glm-5.3-flash`(0.06) 或 `deepseek-v4.1-flash`(0.11) | 极低 | 写单测、改配置、修 lint、批量改名、简单问答 |
| **常规实现** | `deepseek-v4.1-flash`(0.11) | 低 | 采集器、存储层、渲染、CLI、Web 页面等模式固定的模块 |
| **关键节点 / 复杂逻辑** | **`deepseek-v4-pro`(0.51)** | 中 | 算法设计、微妙逻辑、prompt 工程、阶段开场理解架构 |
| 备选（同档） | `kimi-k2.7-code`(0.57) | 中 | deepseek-pro 表现不佳时换 |
| **兜底** | `kimi-k3-1`(1.62) | 高 | **仅在卡死超过 30 分钟且已换过一次模型时** |

⚠️ 不用 `glm-5v-turbo`（v = vision，视觉模型，非编码用途）。

**避免的误区**：不要用 `glm-5.3`/`kimi-k2.8-preview`（0.77-0.79）做常规工作——
它们比 0.5 档贵 50%，但编码场景未必更强。**0.5 档是性价比拐点。**

### 为什么关键档推荐 `deepseek-v4-pro` 而非 `kimi-k2.7-code`

三条理由，第二条最关键：

1. **更便宜**：0.51 < 0.57，单次省 11%
2. **★ 同源知识优势**：本项目要集成的 LLM **就是 DeepSeek**（`deepseek-chat` / `deepseek-reasoner`）。
   用 DeepSeek 模型来写 DeepSeek 集成，它对自家 API 的行为细节、错误响应格式、
   `response_format` 支持情况更熟悉——这对 M3a 的 **json_schema 运行时自动降级**、
   **401/429/5xx 错误分类**这两块尤其有价值（而我们恰恰无法实测，只能依赖模型的先验知识）。
3. **一致性**：SSOT §8.2 定的就是 DeepSeek，配置与 prompt 都围绕它，减少认知切换

> `kimi-k2.7-code` 的定位是代码专精，仍是优质备选；但**在"开发 DeepSeek 集成"这个具体任务上，
> DeepSeek 自家的模型匹配度更高**。

## 三、剩余里程碑的具体分配

| 阶段 | 开场（理解架构） | 实现 | 收尾 | 说明 |
|---|---|---|---|---|
| **M3a** 预言生成 | `deepseek-v4-pro`(0.51) | `deepseek-v4-pro` | 切 Flash 写单测 | **项目灵魂**，不可证伪拦截与置信度校准是微妙判断，值得 0.5 档；且涉及 DeepSeek API 集成，同源模型更准 |
| **M3b** 验证与统计 | Flash(0.11) | Flash | Flash | Brier / 校准曲线是**标准算法**，确定性强，不需要强模型 |
| **M4** Actions+Web+README | Flash(0.11) | Flash | Flash | 工程实现为主，模式固定；**仅 Actions 调试卡住时**升 `deepseek-v4-pro` |
| **M5** 长文+辩论 prompt | `deepseek-v4-pro`(0.51) | Flash | Flash | **prompt 工程**值得 0.5 档设计一次，之后实现用 Flash |

**预计总消耗**：约 4-6 次 0.5 档调用 + 大量 Flash，远低于全程 A 档。

## 四、五个立即可用的省钱技巧

1. **减少往返轮次（最重要）** —— 把需求一次说清楚，比反复补充便宜得多。
   用「开场白模板」就是这个目的：三段式一次给全，避免 Agent 追问。

2. **Flash 档不必为了省 0.05 而切换** —— `glm-5.3-flash`(0.06) 比 `deepseek-v4.1-flash`(0.11) 便宜一半，
   但单次只差 0.05，且切换有质量不确定的风险。**已在用 deepseek-flash 就继续用**，把省钱精力放在减少轮次上。

3. **让 Agent 只读必要章节，不读全文** —— 设计方案已 111KB，全文塞进上下文成本很高。
   每个阶段的开场白都标了「重点章节」，照用即可。

3. **分阶段切模型，不要全程一个** —— 开场用强模型理解架构，实现阶段切 Flash。
   上下文建立起来后，弱模型也能接着做对。

4. **调试时贴最小复现** —— 贴整个文件（几百行）很贵；贴报错 + 相关 20 行即可。

5. **用 Flash 做自检，强模型做设计** —— DoD 自检是机械核对，Flash 足够；
   「拦截规则该多严」这类判断才值得强模型。

---

## 五、一条硬约束：该升档时必须升

保守不等于全程省钱。**出现以下信号立刻升档，不要硬撑**：

- 同一问题连续 2 轮没解决
- Agent 开始顾左右而言他、或产出明显逻辑混乱的代码
- 涉及**不可逆决策**（如预言拒收规则、统计口径）

**理由**：这时继续用弱模型，等于用更多轮次换更差的结果，是最贵的选项。
