# 新增数据源指南

> 面向贡献者。目标：让你在**不读遍整个仓库**的情况下，安全地加一个数据源。
> 分两个难度等级——80% 的需求是 L1（改配置即可），剩下 20% 才需要写代码。
>
> 相关设计：设计方案 §5.0（统一抽象）/ §5.10（环境分级）/ §5.12（可扩展性）。

---

## 0. 先判断你属于哪一级

| 等级 | 适用场景 | 你要做的事 | 预计耗时 |
|---|---|---|---|
| **L1 改配置** | 新增/替换任何 **RSS 或 Atom** 源 | 编辑 `configs/sources.yaml` 的 `rss.feeds`，加一行 | **1 分钟，零代码** |
| **L2 写模块** | 全新类型源（新 API、新站点结构） | 新建一个 `BaseCollector` 子类 + 注册 + fixtures 驱动单测 | **30-60 分钟** |

如果你想加的源恰好有 RSS（很多博客、子版块、GitHub Releases、YouTube 频道都有），**请走 L1**——
不要为了"统一"而写一个专用 collector。

---

## 1. L1：加一个 RSS 源（零代码）

```yaml
# configs/sources.yaml
sources:
  rss:
    feeds:
      - {name: 我的新源, url: "https://example.com/feed.xml", tier: core}
```

字段说明：

| 字段 | 取值 | 含义 |
|---|---|---|
| `name` | 字符串 | 展示名，同时是日志中的 `feed=` 标识 |
| `url` | URL | **必须先用探测脚本验证过**（见下） |
| `tier` | `core` / `optional` | `core` 失败 → 计入失败统计；`optional` 失败 → 只降级告警，不影响退出码 |
| `availability` | `always` / `actions_only` | 本地不可达（DNS 污染/被墙）但 Actions 可达的源标 `actions_only` |
| `title_only` | `true` / `false` | 摘要过短（如只有标题）的源标 `true`：**不参与 TF-IDF 聚类**，权重建议降到 0.35 |
| `weight` | 0-1 | 覆盖源级权重（不填则用 `rss.weight`） |

**验证 URL（必做，红线 10）**：未经实测的 URL 不允许进配置。

```bash
uv run python scripts/probe_sources.py --only rss
```

输出表格里逐 feed 给出：HTTP 状态 / 条目数 / 是否含正文 / 最后更新时间 / 结论。
若源在国内不可达但预期在 Actions 可达，标 `availability: actions_only` 并用 `probe.yml`
工作流（workflow_dispatch）在 Actions 环境复测。

## 2. L2：写一个新采集器

### 2.1 你只需要做两件事

拿数据 → 转成 `RawItem`。**其它全部由框架处理**：限速、重试、缓存、代理、超时、
单源失败隔离、写库、去重、打分、聚类、简报、预言。

```python
# src/aipulse/collectors/my_source.py
from __future__ import annotations

from datetime import datetime
from typing import Any

from aipulse.core.logging import get_logger
from aipulse.normalize.clean import clean_text
from aipulse.schema.items import RawItem, SourceEnum, SourceMetrics

from .base import BaseCollector

log = get_logger(__name__)

API_URL = "https://api.example.com/v1/hot"


def parse_items(payload: dict[str, Any]) -> list[dict[str, Any]]:
    """纯函数：把响应解析成字典列表。放在模块级，便于 fixtures 驱动单测。"""
    results = []
    for entry in payload.get("items") or []:
        if not entry.get("id"):
            continue
        results.append(
            {
                "id": str(entry["id"]),
                "title": clean_text(entry.get("title", "")),
                "url": entry.get("url", ""),
                "summary": clean_text(entry.get("summary", "")),
                "score": entry.get("score"),
            }
        )
    return results


class MySourceCollector(BaseCollector):
    source = SourceEnum.RSS  # ← 见 2.3：新源可能需要扩枚举
    display_name = "我的新源"

    def healthcheck_url(self) -> str:
        """`aipulse doctor` 用它做连通性探针（可选，默认返回 None 表示不探活）。"""
        return API_URL

    async def fetch(self, since: datetime, until: datetime) -> list[RawItem]:
        try:
            response = await self.http.get(
                API_URL,
                source=self.source.value,  # ← 决定用哪个令牌桶（每源独立限速）
                rate_limit=self.cfg.rate_limit,  # ← 必须在 sources.yaml 里配
                params={"since": int(since.timestamp())},
            )
        except httpx.HTTPError as exc:
            # 网络/超时：转成 CollectorError 抛出，编排层会写 source_runs 后继续跑其他源
            raise self.raise_error(f"请求失败：{exc}", cause=exc) from exc
        if response.status_code >= 400:
            raise self.raise_error(f"HTTP {response.status_code}")

        entries = parse_items(response.json())
        if not entries:
            # 空返回是"降级"不是"失败"：记 warning + 返回空列表，绝不抛异常
            log.warning("collector.my_source.empty")
            return []
        return [self._to_item(e) for e in entries]

    def _to_item(self, entry: dict[str, Any]) -> RawItem:
        return RawItem(
            source=self.source,
            external_id=entry["id"],
            title=entry["title"],
            url=entry["url"],  # 写规范 URL（框架会再 canonical_url 一次）
            summary=entry["summary"],
            published_at=entry.get("published_at") or utcnow(),
            metrics=SourceMetrics(points=entry.get("score")),
            extra={"source_weight": self.weight},  # ← 打分层读这个字段
        )
```

### 2.2 注册

```python
# src/aipulse/collectors/registry.py
from .my_source import MySourceCollector

for _cls in (
    GitHubTrendingCollector,
    ...,
    MySourceCollector,  # ← 加在这里
):
    register(_cls)
```

同时在 `configs/sources.yaml` 加配置段：

```yaml
sources:
  my_source:
    enabled: true
    availability: always        # 本地可达；不可达就写 actions_only
    weight: 0.7
    rate_limit: "1/1s"          # 必填：形状 "N/period"，period 支持 s/m/h/d
```

### 2.3 关于 `SourceEnum`

`SourceEnum`（`src/aipulse/schema/items.py`）是**源的白名单**，加新枚举值需要同步改 3 处：
枚举、`_DISPLAY_NAMES`、以及本文档。这是刻意的摩擦——源越多，简报的信噪比越难保证，
**请先确认真的需要新增源，而不是能用现有源 + RSS 覆盖**。

> v1.1 红线：**不得新增任何微信公众号 / X（Twitter）相关的采集器、配置段或环境变量**。
> 这类内容请走 `aipulse inbox add <url>` 手动投喂。

### 2.4 必须遵守的 6 条约定

| # | 约定 | 原因 |
|---|---|---|
| 1 | 只用注入的 `self.http`，禁止 `httpx.get` | 限速/重试/缓存/代理/UA 统一，且测试才能用 respx 拦截 |
| 2 | 不写库、不去重、不调 LLM | 分层职责；这些在 pipeline / normalize / reasoning 里统一做 |
| 3 | 空返回 → 返回 `[]` + warning，不抛异常 | "今天没热点"不是故障 |
| 4 | 网络/解析异常 → `raise self.raise_error(...)` | 编排层据此写 `source_runs.status='failed'` 并隔离该源 |
| 5 | 缺失字段填 `None`，不要填 `0` | `0` 会被打分公式当成真实数据，污染排序 |
| 6 | 部分失败要内部隔离（逐 feed / 逐 subreddit / 逐关键词） | 一个 feed 挂了不该让整个源归零（参考 `rss.py`、`reddit.py`） |

## 3. 单测要求（**fixtures 驱动，硬性**）

红线 2：**禁止凭想象写字段解析**。流程永远是：

```bash
# ① 先拿真实响应落盘（写进 tests/fixtures/）
uv run python scripts/probe_sources.py --only api     # 或 curl 后手动保存
# ② 把 fixture 变成断言（先写测试，后写解析）
# ③ 再实现解析函数，跑测试直到通过
uv run pytest tests/unit/test_collectors_parse.py -q
```

每个新采集器**至少 3 个单测**（`tests/unit/test_collectors_parse.py` 的既有模式）：

| 类型 | 例子 |
|---|---|
| 正常解析 | 从真实 fixture 断言条数与关键字段值 |
| 边界 | 空响应 / 单条 / 窗口内无内容 |
| 异常（脏数据） | 缺 id、缺字段、HTML 结构变更 → 不崩、不编造数据 |

再加一条运行时测试（`tests/unit/test_collectors_runtime.py`，用 `respx` mock）：抓取流程 + 降级路径。
**所有测试都必须无需网络**（CI 无密钥环境必须全绿）。

覆盖率基线：`collectors/` ≥80%（当前 87%）。检查命令：

```bash
uv run pytest -q --cov=aipulse --cov-report=term | grep collectors/
```

## 4. 环境分级（v1.4，务必理解）

本地 WSL 与 GitHub Actions 的网络可达性**不同**。规则：

| 场景 | `always` | `actions_only` |
|---|---|---|
| 本地（未设 `AIPULSE_ENV=actions`） | 正常采集，失败计入统计 | **跳过**，写 `source_runs.status='skipped_offline'`，**不计失败、不影响退出码** |
| Actions（`AIPULSE_ENV=actions`） | 正常采集 | 正常采集 |
| `aipulse doctor` | 正常探针 | 显示"本环境不可达，将在 Actions 启用"，不算 ❌ |

所以：**本地测不到的源不要写死禁用，标 `actions_only` 即可**。

## 6. 常见坑（都踩过，直接抄结论）

| 坑 | 现象 | 解法 |
|---|---|---|
| 依赖易变 CSS class 解析 HTML | 站点改版后静默采到 0 条 | 用稳定结构（标签层次、`itemprop`、文本模式），并准备降级通道 |
| 正则 `r"<p[^>]*>"` | 误匹配 SVG 的 `<path ...>` | 写成 `r"<p(?:\s[^>]*)?>"`（必须有空白或直接闭合） |
| 未处理的时区 | 跨日边界错乱 | 一律 `aipulse.core.timeutil.utcnow()`；源时间先 `ensure_utc` |
| 严格按 24h 窗口过滤 | 索引滞后的源（arXiv 滞后 3-4 天）永远采空 | 该源加 `lookback_days` 配置，并记 warning 说明窗口被放宽 |
| 抓不到就丢条目 | 手动投喂内容消失 | 降级保留（标题退化为 URL），见 `collectors/inbox.py` |
| 坏 gzip 被写进缓存 | 之后一直复现 `DecodingError` | 排查先 `--no-cache`；必要时请求头加 `Accept-Encoding: identity` |
