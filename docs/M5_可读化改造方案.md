# M5 · 可读化改造方案

> 项目负责人读完 weekly.md 与 debate 原文后的反馈：
> 「一堆 it_xxx 编号，内容晦涩难懂，形式也不好，重点不突出，不吸引人看下去。」
> 本文件定位根因、给出改造原则与具体模板样例。

---

## 一、两个文档的问题性质完全不同（关键区分）

| | weekly.md | debate |
|---|---|---|
| **内容质量** | ❌ **差**——大量"这意味着…"句式，实质是数字复述 + 免责声明 | ✅ **好**——四方真的在交锋，有可引用的真判断 |
| **形式质量** | ❌ 差 | ❌ 差 |
| **改造方式** | 形式 + **生成逻辑**都要改 | **主要改形式**，内容要保住 |

### 依据（debate 内容确实好的证据）

- 怀疑派：「用『下期是否有一条非论文类 agent 条目进榜』来证明本期是真实采用，
  但『进榜』正是我方指控的那个有问题的指标——**用一个被质疑的指标去验真，等于没验**」
- 投资派：「供给侧的注意力信号通常要领先付款方信号一到两个季度…
  **用现金流节奏去检验采用节奏，等于设定了一个几乎必然不会被满足的条件**」
- 工程派：「以不可观测作为否证，结论强度就超过了证据能承载的范围」

这些是**真判断**，砍掉就是损失。

### weekly.md 差的证据

```
按斜率判定无可用上升项，故本节不作板块层上升判断；论文与研究来源在窗口内出现整源 0 条，
按采集失败封锁不展开结构性趋势。相邻两日热度上升中，it_42565b5232096036 由 80.53
升至 86.00（+5.47），这是相邻两日、非整周份额的读数，意味着该条目的短窗口关注度出现
一次性抬升，不能据此推成整周板块迁移；该读数只作短窗口观察，不与跨源集合变更日比较。
```

一整段 = 免责声明 + 一个数字 + 一句"这意味着" + 又一句免责。
**通篇是这个模式，读完什么都记不住。**

## 二、根因：我把"防幻觉"做成了"让模型展示工作过程"

我一路加的硬约束，每一条单独看都对，叠加起来毁掉了可读性：

| 我加的约束 | 初衷 | 副作用 |
|---|---|---|
| 结论必须锚定 `item_id + 数字 + 对比` | 防幻觉 | 满屏裸 ID |
| 禁止"消失"，只能说"跌出 Top30" | 挡假话 | 免责声明泛滥 |
| 斜率 + 首末差并列、冲突要标注 | 防过度声称 | 开口先说"无可用上升项" |
| 采集失败必须说明 | 挡假话 | 说明抢在结论前面 |

**核心错误：把"推演过程"当成了"给人看的结论"。**

✅ 正确做法：**机器层看过程，人类层看结论。**

---

## 三、改造原则（五条）

1. **双层分离**：机器层（JSON，保留全部 id/数字/免责）供 L1-L4 校验；
   人类层（Markdown）只给结论。
2. **正文零裸 ID**：改用 `[标题](url)`；ID 收进文末「数据溯源」区。
3. **免责声明不占正文**：收进 `<details>` 折叠块（GitHub 原生支持）。
4. **结论前置**：开头「本周三句话」，一眼看到重点。
5. **视觉锚点**：emoji 小标题 + 表格 + Unicode 条形图，不引额外依赖。

## 五、debate 新模板要点

**内容保住，只改容器。**

| 现状 | 改后 |
|---|---|
| 开场直接进入四方长篇 | 开头放**结论卡片**（共识/分歧/置信度） |
| 每方 400-700 字散文 | 立场一句话 + 核心论据 3 条 + 折叠全文 |
| Round 2 每方 6-7 条质证（极长） | 收敛为**交锋矩阵**表格（谁质疑谁 / 要点 / 是否让步） |
| 证伪条件长句三段式 | **表格**：断言 ｜ 观测什么 ｜ 成立→ ｜ 不成立→ |

**Round 2 质证的精华必须保留**，只是换容器：

| 质疑方 → 被质疑方 | 核心一击 | 结果 |
|---|---|---|
| 怀疑派 → 乐观派 | 用被质疑的指标去验真 = 没验 | 乐观派收窄 |
| 投资派 → 工程派 | 2-3 周测季度级信号必然得零 | 工程派坚持 |
| ... | | |

## 五之二、三句话生成规则（S5 实现时补）

`prompts/trend/headlines.j2` —— 第 8 次调用，把 7 节正文压成人类层结论。

**规则（防又写成免责声明）**

- 只输出三句判断句，每句 **≤40 字**
- 禁止免责措辞：`这意味着` / `不能据此` / `只作观察` / `不作判断` / `仅供参考` / `需要说明` / `由于数据`
- 禁止裸 `it_` 编号
- 三句按重要性排序：变化最大的信号排第一

**同时产出 `judgements`**：每节一条判断性结论（≤60 字），
`claim` 里**不得出现编号**，编号单独放 `cited_item_ids`——
渲染器负责把编号转成 `[标题](url)`，正文因此保持零裸 ID。

**分工**：表格数字由 `analysis/cross_period` 确定性渲染（不经模型，不会幻觉）；
三句话由模型提炼（"哪三个信号最重要"是判断，不是计算）。

## 六、产物路径（按项目负责人要求：清晰简洁 + 分日期）

```
data/reports/
├── 2026/10/23/            ← 每日报告（不变）
├── trend/
│   └── 2026-10-22/        ← 按【窗口结束日】建目录
│       ├── weekly.md      人类版（新）
│       ├── weekly.json    机器版（现有结构，供 L1-L4）
│       ├── selfcheck.md / selfcheck.json
│       ├── watchlist.json
│       └── calibration.json
└── debate/
    └── 2026-10-22/        ← 同一天可放多个话题
        └── <slug>.md / <slug>.json
```

★ 不再用固定名 `weekly.md` 覆盖——**同名覆盖会丢掉跨期对比历史**，
而 L3/L4 自验证最需要的就是跨期。

## 八、双层分离：机器层是 L1-L4 的输入源（S5 实现时补）

新模板与旧 L1 有三处硬冲突（L1 原本读 `weekly.md` 的 `## N.` 结构）：

| L1 的硬要求 | 新模板 |
|---|---|
| 7 个 `## N. 上升主题…` 小节齐全 | 没有，改成了三张表 |
| 每节至少 1 个裸 `item_id` | 正文零裸 ID |
| 全文 2000-4000 字 | 约 1000 字 |

**解法（项目负责人定）**：L1-L4 改读 `weekly.json` 机器层。

- `weekly.json` 升级为完整机器层：7 节正文 + cited ids + violations + caveats（免责口径）。
- `selfcheck` 用 `sections_from_machine()` 把它还原成与 `parse_markdown` 同构的 `sections`，
  **四层判定逻辑一行未改**，只是输入源换成 JSON。
- 状态文件（`watchlist.json` / `calibration.json`）随目录拆分，
  `_load_state()` 改为**合并各期目录**，否则跨期历史会丢——而 L3/L4 要的正是跨期。
